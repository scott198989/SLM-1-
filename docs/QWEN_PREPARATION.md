# Qwen preparation and the training gate

Only the three tokenizer/config assets were fetched at the pinned model revision. No model weights, optimizer, GPU training dependencies or training job were downloaded/started. CPU preparation uses the real tokenizer and original official chat template, not cl100k_base. The 0.22.2 tokenizer is within the proposed Transformers constraint; a second 0.23.2 audit produced identical corpus totals. This is not a GPU runtime compatibility test.

## Formatting and supervision

`QwenFormatter` verifies asset hashes, text roles/turn order and template controls. It preserves the official empty think wrapper rather than inventing chain-of-thought. Input/system/user text, assistant headers, separators and padding have loss label -100; assistant content and each `<|im_end|>` are supervised. The base config EOS is 151643 while the chat end is 151645. Use 151645 to stop chat generations;151643-valued padding remains ignored. Do not append a second EOS or use the base EOS blindly as chat termination. The original template has no generation-mask tags, so an assumed `assistant_only_loss` trainer switch is insufficient: pass the already-tested labels and retain them through the collator. Multi-turn and Unicode masks, repeated end tokens and padding were tested against the actual template offsets.

All 34,463 records were examined:34,462 formatted; one embedded template-control record was rejected. Total 2,033,523 formatted tokens;1,354,641 assistant tokens. Lengths are short (median 47,95th percentile 132,maximum 318). No existing example exceeds 2048. These figures include unapproved/quarantined data and are not a training release. Future Drive worked solutions may be longer; preflight rejects overflow without silent truncation or answer loss. The model config context is 32768; a tokenizer metadata value does not establish usable 131072-token training.

## GPU proposal and MoE compatibility

The proposed exact package versions and settings are in `configs/qwen-qlora-proposal.json`. They have published package metadata and compatible core constraints; they have not been installed or exercised together on the desktop. A full transitive lock and runtime compatibility test remain mandatory. Pinned Transformers 4.57.6 represents Qwen experts as ModuleList blocks with gate/up/down nn.Linear layers. This matters because newer fused expert parameters can bypass ordinary linear quantization/LoRA assumptions and leave huge full-precision tensors. The inspected source hash and locations are retained in the runtime evidence manifest.

The first proposal adapts attention q/k/v/o projections only, rank 16,13,369,344 estimated trainable parameters. Freeze router and experts while quantizing their base weights. After an authorized model load, inventory every expert's dtype/class/bytes and assert expected four-bit storage; do not infer success from `load_in_4bit=True`. Do not target all experts or transplant a legacy tokenizer/head/neural core. The active 3.3B parameters do not remove the need to keep approximately 30.5B total parameters resident.

The 32 GiB RTX 5090 may fit this restricted QLoRA proposal at batch 1/context 2048, but 20–29 GiB peak is an estimate, not a measurement or guarantee. CUDA12.8+ Blackwell support, BF16, available RAM/storage and actual desktop configuration must be checked. The 4 GiB laptop is for preparation. Reject a peak above 29 GiB; do not silently offload or increase context. After authorization, run a 20-step memory pilot, discard its adapter, reset seed/data order and compare a frozen base baseline before actual training. Record allocated/reserved/peak VRAM and RAM; test checkpoint reload and label preservation. Saving/resuming an adapter alone does not restore optimizer/scheduler/RNG/data position.

Freeze dataset and family hashes, source/tokenizer/runtime revisions, template/render hashes, seeds, decoder, tools and RAG index. Record environment lock, driver/CUDA, training/evaluation configs, checkpoints, optimizer/scheduler/RNG state and data position. Select checkpoints using separate development families, not sealed gold. Require independent baseline-versus-adapter results under identical tools, references and decoder. No measured expected score gain is available.
